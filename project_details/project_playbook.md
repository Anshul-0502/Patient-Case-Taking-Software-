# Phase 1.1 – Complete Patient Registration Module

## Module Objective

Build the complete **Patient Registration Module** for the Patient Case-Taking Software.

The purpose of this module is to collect the patient's basic personal and health-related information, validate the entered data, create a patient profile, securely store the information in the database, and redirect the patient to the Patient Dashboard after successful registration.

This module must remain simple and user-friendly.

Do not collect detailed symptoms, detailed medical history, previous treatments, medicines, current complaints, or previous medical reports in this module.

Those details will be collected later through the AI Consultation Module.

---

# Main Registration Requirements

Create a dedicated page named:

**Patient Registration**

The registration form must contain the following fields:

1. Full Name
2. Date of Birth
3. Gender
4. Mobile Number
5. Email Address
6. Address
7. Blood Group
8. Height
9. Weight
10. Existing Diseases
11. Register Button

# 1. Full Name

## Description

Collect the complete name of the patient.

## Field Type

Text Input

## Required

Yes

## Validation

- Field cannot be empty.
- Remove leading and trailing spaces.
- Prevent invalid input.
- Use a reasonable maximum character limit.
- Display a validation message if the field is empty.

Please enter your full name.

# MODULE 2 – AI CONSULTATION

## Module Overview

The AI Consultation Module is the core intelligent module of the Patient Case-Taking Software.

The purpose of this module is to allow the patient to explain their current health problem naturally through voice interaction instead of completing a long manual medical questionnaire.

The module must collect patient case-taking information, ask relevant follow-up questions dynamically, process previous medical reports if uploaded, generate structured patient documentation, allow the patient to review and correct the generated information, and finally generate a physician-ready Patient Case Report.

The AI Consultation Module must not independently provide the final medical diagnosis.

The AI is responsible for:

- Collecting patient information
- Understanding the patient's chief complaint
- Asking relevant follow-up questions
- Structuring patient-provided medical information
- Processing uploaded previous medical reports
- Extracting useful medical information from documents
- Generating structured Patient Case Documentation
- Creating a Patient Report Summary
- Allowing patient review and correction
- Generating the final report after confirmation

The doctor remains responsible for:

- Physical examination
- Clinical assessment
- Final diagnosis
- Prescription
- Treatment
- Final medical decisions

# PHASE 2.1 – AI VOICE ASSISTANT

Build the complete AI Voice Assistant for patient case-taking.

The AI Voice Assistant must communicate naturally with the patient and collect relevant information about the patient's current health problem.

The AI must understand the context of the conversation and dynamically generate relevant follow-up questions.

# Chief Complaint Collection

The AI must begin the actual patient case-taking conversation using an open-ended question.

Recommended question:

What problem are you facing today?

The AI should not initially provide examples of symptoms.

Do not begin with questions such as:

Do you have fever, cough, headache, cold, stomach pain, or weakness?

The patient must be allowed to explain the problem naturally without being influenced by suggested symptoms.

Example:

AI:

What problem are you facing today?

Patient:

I have had fever and cough for the last three days.

---

# Chief Complaint Data

The system should identify and structure the main complaint.

Example:

Chief Complaint:
Fever and cough

Duration:
Three days

Original Patient Statement:
I have had fever and cough for the last three days.

The original statement may be retained along with structured information.

---

# Dynamic Follow-Up Questions

The AI must dynamically generate follow-up questions based on the patient's previous answers.

The consultation must not use exactly the same fixed questionnaire for every patient.

The next question should depend on:

- Chief complaint
- Previous patient response
- Duration
- Severity
- Associated symptoms
- Current context
- Medicine information
- Relevant existing diseases
- Relevant previous medical information

---

# Example Dynamic Conversation

AI:

What problem are you facing today?

Patient:

I have had fever and cough for three days.

AI:

When did the fever first start?

Patient:

Three days ago.

AI:

Is the fever continuous or does it come and go?

Patient:

It comes and goes.

AI:

Are you experiencing any difficulty breathing?

Patient:

No.

AI:

Have you taken any medicine for the fever?

Patient:

Yes, I took paracetamol.

AI:

Did the medicine help?

Patient:

It reduced the fever for some time.

The AI must continue asking only questions relevant to the patient's reported problem.

---

# Information to Collect During Consultation

The AI Voice Assistant should collect relevant case-taking information such as:

## Chief Complaint

- Main health problem
- Patient's own description
- Primary symptoms

## Duration

- When the problem started
- How long the problem has been present

## Symptom Progression

- Improving
- Worsening
- Stable
- Intermittent
- Continuous

## Severity

Collect severity information where relevant.

## Associated Symptoms

Ask about additional symptoms only when relevant to the chief complaint.

## Medicine Information

Collect:

- Medicine already taken
- Medicine name if known
- Duration
- Patient-reported response

## Existing Medical Conditions

Use known information from registration where relevant.

The AI can ask for additional details if necessary.

## Previous Similar Problem

The AI may ask whether the patient experienced a similar problem in the past.

## Previous Relevant Treatment

Collect previous treatment information if it is relevant to the current complaint.

## Additional Relevant Information

The AI may collect other case-taking information required to create a meaningful physician-ready report.

---

# Conversation Context Management

The AI must maintain context throughout the consultation.

Example:

If the patient has already said:

The fever started three days ago.

The AI should not repeatedly ask:

When did the fever start?

The system should remember previously collected information and avoid unnecessary repetition.

---

# Avoid Duplicate Questions

Before generating the next question, the AI should check:

- Has this information already been collected?
- Has the patient already answered this question?
- Is the question relevant to the current complaint?
- Is additional clarification necessary?

Only ask the next question if useful information is still required.

---

# Patient Correction During Conversation

If the patient corrects something they said earlier, the AI should update the consultation context.

Example:

Patient:

I said two days earlier, but actually the fever started three days ago.

The stored consultation information should be updated accordingly.

---

# Conversation Transcript

Display a readable transcript during consultation.

Example:

AI:
What problem are you facing today?

Patient:
I have had fever for three days.

AI:
Is the fever continuous?

Patient:
No, it comes and goes.

The transcript should clearly distinguish between:

- AI messages
- Patient messages

---

# Voice Failure Handling

If speech recognition fails, display a message such as:

I could not understand that clearly. Please try again.

The patient should be allowed to speak again.

Do not end the consultation because of one failed voice input.

---

# Microphone Permission

If microphone access is required and permission is not available, display an appropriate message.

Example:

Microphone access is required for voice consultation.

Please enable microphone permission and try again.

---

# Consultation Pause

If supported by implementation, the patient may temporarily stop voice interaction without losing the collected information.

The consultation state should remain available during the active session.

---

# Upload Previous Report Option

During the AI Voice Consultation, display an optional button:

Upload Previous Report

The patient should not be forced to upload a medical report.

The consultation must work even if no report is uploaded.

Detailed document processing is defined later in Phase 2.3.

# Password Security

Passwords must:

- Never be stored in plain text
- Use secure hashing
- Follow reasonable password requirements
- Be transmitted only through secure connections

---

# Role-Based Security

Every sensitive backend operation must verify:

Authenticated Admin
↓
Admin Role
↓
Required Permission
↓
Allow / Reject Action

Do not rely only on frontend menu visibility.

---

# Patient Privacy

Admins should only access patient information required by their authorized role.

Example:

Pharmacy Staff should not automatically receive full access to unrelated AI consultation data.

Use least-privilege access.

---

# File Upload Security

Validate uploaded:

- Doctor Profile Images
- Prescriptions if used
- Lab Reports
- Other Admin Documents

Validate:

- File Type
- File Size
- File Signature where supported
- Access Permissions

Do not allow executable file uploads.

# Important Module 9 Rules

- Keep Hospital Admin Portal completely separate from Patient Dashboard.
- Only authorized hospital users can access admin functionality.
- Implement role-based access control.
- Do not give every hospital user full administrative permissions.
- Validate all permissions on the backend.
- Protect patient medical information.
- Use least-privilege access.
- Never store admin passwords in plain text.
- Protect admin sessions.
- Validate all admin input.
- Validate all uploaded files.
- Protect lab report files.
- Prevent unauthorized patient record access.
- Prevent unauthorized appointment manipulation.
- Prevent duplicate appointment slot assignment.
- Preserve historical records where required.
- Prefer deactivation or archival over unsafe permanent deletion where appropriate.
- Use confirmation for high-impact operations.
- Maintain audit logs for important administrative actions.
- Doctor information should flow to patient Doctor Directory.
- Doctor schedules should flow to Appointment Booking.
- Pharmacy data should flow to Hospital Pharmacy.
- Lab data should flow to Lab Test Booking.
- Lab reports should securely flow to patient report access.
- Department data should flow to Hospital Services.
- Ambulance status should flow back to the patient.
- Hospital announcements should flow to Notification Center.
- Analytics should focus on operational summaries and avoid unnecessary sensitive patient details.
- Keep the complete portal secure, structured, professional, scalable, and easy for authorized hospital staff to operate.
